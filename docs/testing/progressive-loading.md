# 渐进加载验收

本页用于维护者检查 v7 的任务路由与安全边界。结构测试、静态路由核对和真实客户端执行是不同证据：通过前两项不能宣称已完成 Codex/ZCode/Claude Code 端到端测试。

## 体积基线

相对 v6 提交 `83b7777`，以下为 UTF-8 文件字节数，不是 tokenizer 计数或费用估算：

| 项目 | v6 | v7 |
|---|---:|---:|
| SKILL.md | 40,522 | 7,674 |
| 标准 AGENTS 桥接 | 3,282 | 868 |
| 简单开发启动的静态协议组合 | 58,372 | 23,189 |
| 纯 Worklog 查询的静态协议组合 | 43,804 | 13,404 |

组合值是依赖路径求和，不是客户端运行追踪。开发示例假设内置 Codex/ZCode、合法配置、无迁移差异、无待补录且不需额外主题检索：v6 为入口 + 桥接 + rule-loading + auto-migration；v7 为入口 + 桥接 + configuration + startup + rule-loading + migration-check。查询示例 v7 为入口 + 桥接 + configuration + worklog-query。文件只按一份计算；不包括项目指令、实际配置、索引、规则正文、代码、工具封装和对话内容。

实际任务涉及自定义适配器、知识检索、写入、规则歧义或迁移时会加载更多文件；应读取的强制规则不能为了达到预算而截断。文件大小变化后更新此基线；精确 token 统计应指定客户端、模型/tokenizer 和冷/热会话条件。

## 可重复的场景检查

使用临时测试仓库和临时 Vault，不指向真实项目。通过正常初始化创建测试配置，再保留文件内容/时间戳快照用于比较。每个冷启动场景使用独立会话，记录读取的资源、实际写入及失败项；不要将推演计入真实 Worklog。

| 场景与输入 | 应发生的行为 | 不应发生的行为 |
|---|---|---|
| 新会话：只读检查一处 README 文案，配置/桥接均最新 | startup、适用规则及轻量检查；报告来源 | 安装更新、初始化、写日志、加载所有模板 |
| `/kb-today`，当天没有日志 | configuration + worklog-query；报告“无记录” | 扫描其他项目或声称“今天没有工作”、创建日报 |
| `/kb-report week` 后再请求 `--save` | 查询只读；save 前加载写入规则、安全协议和 Worklog 模板，保存快照并验证 | 查询阶段写入；保存阶段跳过锁/去重；无差别加载笔记模板 |
| 修复已有任务并通过测试，没有永久知识 | 匹配任务 ID，progress + worklog-write + write-safety，成果只记一次 | 自动升级全局包、重复落账、强行创建永久笔记 |
| 保存含义明确的 ADR；随后保存一条共享 Rule | ADR 读取知识模板；Rule 才增加 rule-maintenance 与规则模板，核对共享授权 | 把 ADR 强套规则正文；单项目事实自动变全局 Mandatory |
| 首次 `/kb-init` 后原样再执行一次 | 初次取得 Vault/项目/客户端选择，创建缺失目标；重跑零内容差异、零备份 | 读取日报/知识笔记模板、重写用户非托管指令 |
| v6 授权有效，B 项目桥接落后，Shared 已整理 | gate 发现差异后才进入 auto-migration/project-migration，更新 B 的托管区块；Shared 无差异不写 | 下载/重装 Skill、扫描 C 项目、把本次等价重排当任意未来授权 |
| 同一 B 项目重复启动，内容无变化 | 轻量检查结束，不加载迁移执行和初始化流程 | 创建“检查完成”事件或新备份 |
| 有迁移差异但任务明确只读，或授权 Disabled/损坏 | 汇总 Pending，兼容加载现有规则 | 静默开启授权或创建锁、备份、目录 |
| 旧 Mandatory 无 load，或命中超过 5 条规则 | 完整读取兼容/命中规则；条件不明时澄清 | 套用知识 top-k 截断、为省 token 降低强度 |
| 来源元数据已迁移，Catalog 漏更新 | 发现源/目录差异；有授权时对账目录，其他来源不重写 | 仅凭桥接版本/成功标记判定已完成 |
| 任务新增构建/迁移操作、上下文丢失或文件变更 | 重筛选并补读相关协议与规则；写前重读目标 | 以会话缓存为理由继续使用旧约束 |
| 写锁冲突、模板缺失或桥接标记损坏 | 明确 Pending，保护原文件和非托管内容 | 按锁年龄清锁、猜测模板或报告全部成功 |

第一次验证应记录使用的实际 Skill 安装路径，避免仓库已更新却仍加载旧全局副本。旧桥接/宿主缓存的广泛读取要求在托管更新和必要刷新前仍须遵守。

## 自动化包检查

```bash
python3 tools/validate_skill.py skills/manage-obsidian-project-kb
python3 -m unittest discover -s tests -v
```

检查入口 8,000 字节预算、桥接 1,200 字节预算、必需模块/模板、跨资源引用、路径边界和桥接/模板标记。测试包含故意缺少资源、嵌套断链、越界引用和超预算的包；这些检查不通过匹配指令措辞来声称行为安全。真实客户端行为仍按上表验证。
