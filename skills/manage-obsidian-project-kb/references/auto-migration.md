# Global installation, lazy project migration

用于启用自动迁移、启动时检查已初始化项目，以及诊断/撤销自动迁移。它不是后台服务：必须由客户端实际加载本 Skill 才能运行。更新全局包一次，不等于所有项目文件已立即更新。

## One-time authorization and local state

`/kb-upgrade --auto-migrate` 或明确要求“今后使用同一份 Skill 时自动迁移已有项目”，授权本次兼容协议 `bridge-v6-rule-loading-v1`。先简短说明后续会修改已初始化项目的托管桥接、相关 Shared/项目规则及必要索引、备份和 Worklog，再执行；无需逐项目再次请求同一授权。单纯安装/复制 Skill、普通 `/kb-init` 或未带此选项的首次 `/kb-upgrade` 不自动产生跨项目授权。

授权仅针对本协议的保守兼容迁移，不包括未来任意版本迁移、改绑 Vault、初始化新项目、清锁、废弃规则、扩大规则范围或执行业务/运维操作。用户的新限制与宿主权限始终优先。

用户仅要求“启用当前安装的自动迁移”时，核验当前包包含本协议所需资源后直接记录授权，不必联网或重装；没有当前项目配置也可以单独启用。此操作不自动启动新项目初始化。

机器本地状态放在以下位置，不放进 Skill 包、代码仓库或同步的 Vault：

- POSIX：有效的绝对路径 `$XDG_STATE_HOME/manage-obsidian-project-kb/installations.json`；未设置时使用用户主目录下 `.local/state/manage-obsidian-project-kb/installations.json`。环境变量为相对路径时不使用。
- Windows：已解析的 `%LOCALAPPDATA%/manage-obsidian-project-kb/installations.json`。无法确定本机状态目录时报告 Pending，不静默换到项目中。

```json
{
  "schema_version": 1,
  "installations": [
    {
      "installed_path": "/absolute/path/to/manage-obsidian-project-kb",
      "auto_migrate": "OnUse",
      "authorized_migrations": ["bridge-v6-rule-loading-v1"]
    }
  ]
}
```

以实际安装目录解析软链接后的规范化绝对路径匹配记录；同一物理包只一条。不同客户端共享同一物理包时复用记录；独立副本、移动后的安装或其他机器不能借用授权。项目绑定的唯一来源仍是项目 `.ai/obsidian-kb.json`；此状态不保存项目清单，不替代项目配置。

仅在完整新版包验证成功后记录授权。可在同条记录中保存已核实的 `source`、`revision`，供后续显式升级复用；不得保存凭据或含认证参数的 URL。无授权记录、JSON 损坏或不支持的 schema 均不视为启用，报告而不重建覆盖。

写状态时使用同目录的 `.installations.lock/` 原子获取互斥，记录随机 operation_id 与 owner；只释放自己的锁，不按年龄清除。获锁后重读、保留其他安装记录、比较差异，变化时私有备份并原子替换、读回验证；相同内容零写入。该锁只保护本机状态，写完即释放，不能持有它再获取 Vault 锁。权限失败报告“自动迁移未启用”，当前项目已获授权的升级可独立继续。

用户要求关闭自动迁移时，将当前安装记录的 `auto_migrate` 改为 `Disabled`，不回退已完成迁移。只关闭时不联网、不更新包、不迁移项目；后续恢复需明确授权。`--check` 始终只读，即使同时出现 `--auto-migrate` 也只预览。

## On-use gate

启动对齐时先校验当前项目配置、加载现有适用规则，再检查当前安装的有效授权。规则加载仍应考虑拟进行的兼容迁移；不能以迁移为理由跳过旧桥接明确要求的规则。桥接替换后重新读取新版规则协议；宿主不能刷新指令时说明需新会话，本会话保留更保守的已加载约束。

| Situation | Action |
|---|---|
| 已授权本协议 + 已初始化项目 + 当前为允许写入的任务 | 业务修改前自动对账当前项目，无需用户再运行升级命令。 |
| 只读问答、审查、计划、`--check`、doctor/status/read/today 或不带 save 的 report | 仅检查并汇总待迁移项，不创建状态、锁、目录、备份或日志；下次可写任务再迁移。 |
| 无配置或配置/绑定非法 | 不从全局状态推断绑定或自动创建配置；正常初始化需用户选择，非法配置先修复。 |
| 无授权、授权关闭、协议 ID 不匹配或状态不可读 | 不自动写入；有迁移需求时提示一次启用方式，继续现有兼容加载。 |
| 已完成且实际内容无差异 | 零写入、零备份、零工作事件，不每轮重复成功提示。 |

一旦用户明确授权迁移本身，即可执行迁移，不必等待另一个代码修改任务。只读任务的明确限制优先于历史授权。

## Reconcile without reinstalling

1. 使用当前完整安装包，**不联网查版本、不下载、不再次安装，不调用完整 `/kb-upgrade`，不扫描其他代码项目**。复用本轮已发现的规则元数据，先检查配置、桥接、元数据缺项与 Catalog 差异，仅对待迁移或存在冲突的来源读取必要正文；合法元数据且 Catalog 一致的未命中规则不为升级重复全文加载。记录当前项目/Shared 的实际差异；已迁移的 Shared 按实际内容 no-op，不盲信其他项目的完成标记。发现高于本包支持的配置或桥接协议时保留原状并报告，不降级。
2. 复用 `references/upgrade.md` 第 3–5 节（已有项目路径）：配置/客户端选择不变，受管理桥接更新至 v6；Shared 与当前项目规则按原有条件保守迁移；对账 Catalog。自动流程不进入新项目初始化向导，不写项目来源记录。用户明确限制了本项目范围时遵守该限制。
3. 复用现有私有备份、Git 本地忽略、锁顺序和最小补丁。需要多层写入时先获取 Shared 锁再获取项目锁；项目配置/桥接对账也在项目锁内，不得持有项目锁后再请求 Shared 锁。内层流程复用本操作已持有的锁，不重复获取。获锁后重读来源，防止另一 Agent 已迁移后重复落账。
4. 读回验证并重算差异，按稳定事件 ID 仅记录实际迁移一次。来源已迁移但 Catalog 漏更新时仍须补齐；不以桥接版本或成功标记代替来源校验。无变化不更新日期，不创建“已检查”日志。
5. 歧义规则保留原状和兼容加载，集中报告 Pending，不反复逐条询问。失败后根据实际文件重试剩余步骤，不重装全局包。只有缺失/冲突规则妨碍当前工作时暂停受影响业务修改；独立业务工作不必被无关迁移失败阻塞。

最终区分：全局安装版本、自动迁移是否启用、当前项目迁移结果、共享层结果及 Pending。不宣称其他尚未访问的项目已迁移。旧桥接能加载新版 Skill 时可进入此流程；桥接缺失、宿主未加载 Skill 或缓存旧包时无法自动触发，需要显式调用 Skill 或刷新会话，而不是每项目重新安装。
